# PR7 - Modèle préinstallé Maintenance préventive

## Objectif

PR7 complète le modèle préinstallé `preventive_maintenance` utilisé par l'onglet `Rapport` des interventions.

Le périmètre reste limité à la configuration du modèle : nature d'intervention, modèle, sections, champs, options et mappings prestations -> sections. Le PDF complet de maintenance préventive n'est pas implémenté dans cette PR.

## Nature et modèle

La nature d'intervention préinstallée est :

| Code | Libellé | Modèle associé | Maintenance | Préventive | Rapport requis | Signature requise |
|---|---|---|---:|---:|---:|---:|
| `PREVENTIVE_MAINTENANCE` | Maintenance préventive | `preventive_maintenance` | Oui | Oui | Oui | Oui |

Le modèle de rapport préinstallé est :

| Code | Libellé | Cible | Actif | Défaut |
|---|---|---|---:|---:|
| `preventive_maintenance` | Rapport de maintenance préventive | `fichinter` | Oui | Oui |

## Sections préinstallées

Sections toujours présentes :

- `GENERAL_INFORMATION` : Informations générales ;
- `EQUIPMENT_SUMMARY` : Matériel / installation ;
- `INSTALLATION_DESCRIPTION` : Descriptif installation ;
- `GENERAL_OBSERVATIONS` : Observations générales ;
- `CUSTOMER_SIGNATURE` : Signature client.

Sections conditionnelles selon prestations :

- `PANEL_CLEANING` : Nettoyage panneaux ;
- `INVERTER` : Onduleur ;
- `ELECTRICAL_BOX` : Vérifications coffrets ;
- `DC_ELECTRICAL_MEASURE` : Mesures électriques DC ;
- `PRODUCTION_READING` : Relevés production/consommation ;
- `ROOF` : Opérations en toiture ;
- `THERMOGRAPHY` : Thermographie.

Les sections de base reçoivent au moins un champ de modèle, car l'onglet Rapport n'affiche pas une section sans champ.

## Champs et points de contrôle

La section `INVERTER` contient les contrôles demandés sur interrupteur DC, ventilation, continuité MALT, bouchons USB/MPPT, enveloppe et étiquettes, serrage, fonctionnement au départ et puissance au départ.

La section `ELECTRICAL_BOX` contient les contrôles visuels, nettoyage/lubrification, raccordements, mise à la terre, sectionneur, différentiels, parafoudre et arrêt d'urgence.

La section `DC_ELECTRICAL_MEASURE` contient référence string, tension à vide DC, polarité, isolement, isolement +/terre, isolement -/terre et observation.

La section `PRODUCTION_READING` sépare chaque métrique en deux champs numériques : `N-1` et `N`. Les codes historiques restent les valeurs `N`, et les nouveaux codes `*_N_MINUS_1` portent les valeurs `N-1`. Une observation de section est ajoutée.

La section `ROOF` contient les contrôles sur abergements, panneaux, nettoyage, fixation, chemins de câble, câbles sous modules et mises à la terre.

La section `THERMOGRAPHY` contient les champs de réalisation, date/heure, météo, température, irradiance, caméra, zone concernée, températures, anomalie, type d'anomalie, criticité, préconisation et photos.

Options `THERMO_ANOMALY_TYPE` :

- `HOT_SPOT` : Point chaud ;
- `CELL_DEFECT` : Cellule défectueuse ;
- `BYPASS_DIODE_SUSPECT` : Diode bypass suspecte ;
- `CONNECTION_HEATING` : Connectique échauffée ;
- `SHADING` : Ombrage ;
- `SOILING` : Encrassement ;
- `PERFORMANCE_DIFFERENCE` : Différence de performance ;
- `OTHER` : Autre.

Options `THERMO_CRITICALITY` :

- `LOW` : Faible ;
- `MEDIUM` : Moyenne ;
- `HIGH` : Élevée ;
- `CRITICAL` : Critique.

## Idempotence

Le seed d'activation insère uniquement les lignes absentes selon les clés techniques stables :

- `entity + code` pour les dictionnaires ;
- `entity + code` pour le modèle ;
- `entity + fk_report_template + code` pour les sections ;
- `entity + report_template_code + code` pour les champs ;
- `entity + fk_report_template_field + code` pour les options ;
- prestation + section pour les mappings.

La réactivation ne doit pas créer de doublon et ne doit pas écraser les personnalisations utilisateur. Les migrations ne remplissent que les liens techniques manquants (`fk_report_template`, `fk_report_template_section`) et ne réinitialisent pas les flags d'administration comme `active`, `position`, `visible_form`, `visible_pdf`, `readonly` ou `is_required`.

Quelques anciennes valeurs de défaut connues sont renommées de manière conservatrice, uniquement si la valeur courante correspond encore exactement à l'ancien défaut. Un libellé, une option ou une portée déjà personnalisés sont conservés.

## Comportement attendu

- Sur une activation neuve, le modèle `preventive_maintenance` est disponible dans l'administration des modèles de rapport.
- La nature `PREVENTIVE_MAINTENANCE` est liée au modèle et permet de générer un rapport depuis l'onglet `Rapport` d'une intervention.
- Une réactivation ne crée pas de doublon.
- Un modèle modifié par l'utilisateur reste modifié après réactivation.
- Le modèle reste éditable et duplicable depuis l'administration existante.
- Les rapports déjà créés restent des snapshots figés ; les nouveaux champs apparaissent seulement sur les nouveaux rapports, aperçus ou recalculs depuis le modèle.
