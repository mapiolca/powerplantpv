# PowerPlantPV v1.3 PR1 - Socle données maintenance

Copyright (C) 2026  Pierre Ardoin <developpeur@lesmetiersdubatiment.fr>

## Objectif

Cette étape prépare uniquement le socle données de maintenance préventive. Elle ne livre pas encore les écrans complets de rapport, la génération PDF, la signature du rapport, les calculs de maintenance ou les traitements métier d'intervention.

## Tables ajoutées

Les tables suivantes sont créées par les fichiers SQL dédiés et reprises dans `sql/dolibarr_allversions.sql` :

- `llx_c_powerplantpv_intervention_nature` : dictionnaire des natures d'intervention.
- `llx_c_powerplantpv_maintenance_service` : dictionnaire des services de maintenance.
- `llx_c_powerplantpv_report_section` : dictionnaire des sections de rapport.
- `llx_c_powerplantpv_index_type` : dictionnaire des types de relevés.
- `llx_powerplantpv_maintenance_service_section` : liaison normalisée entre services de maintenance et sections de rapport.
- `llx_powerplantpv_report_template_field` : définition des champs du gabarit de rapport.

Toutes les tables métier ou de dictionnaire portent `entity`. Les liaisons utilisent des colonnes `fk_*` et ne recopient pas les libellés des dictionnaires sources.

## Données par défaut

L'activation du module insère de manière idempotente, pour l'entité courante :

- la nature `PREVENTIVE_MAINTENANCE` ;
- les services de maintenance attendus par le cahier des charges ;
- les sections de rapport de maintenance préventive ;
- les types de relevés de production, injection, consommation et production annuelle ;
- les liaisons services/sections ;
- le gabarit de champs `preventive_maintenance`.

Les insertions vérifient l'existence d'une ligne équivalente avant création. Une ligne déjà personnalisée n'est pas écrasée lors d'une réactivation.

## Champs complémentaires

L'activation ajoute les extrafields suivants s'ils sont absents :

- `contrat.powerplantpv_maintenance_recurrence` : récurrence contractuelle de maintenance.
- `contrat.powerplantpv_next_maintenance_period_start` : début de prochaine période.
- `contrat.powerplantpv_next_maintenance_period_end` : fin de prochaine période.
- `product.powerplantpv_maintenance_services` : services de maintenance portés par un produit ou service.
- `fichinter.powerplantpv_intervention_nature` : nature d'intervention de la fiche intervention.

Les champs sont conditionnés par `POWERPLANTPV_MAINTENANCE_ENABLE`.

## Droits

Le descripteur déclare les droits :

- `powerplantpv / maintenance / read`
- `powerplantpv / maintenance / write`
- `powerplantpv / maintenance / delete`
- `powerplantpv / maintenance / report`
- `powerplantpv / maintenance / config`

Ces droits préparent les écrans et API des étapes suivantes ; cette PR ne crée pas de contrôleur métier complet.

## Multicompany

Les dictionnaires maintenance sont exposés dans la définition de partage Multicompany du module. Les données par défaut sont insérées dans l'entité active et les requêtes des dictionnaires natifs filtrent sur cette entité.

Point de vigilance : l'édition manuelle des lignes via l'administration native des dictionnaires dépend du comportement `admin/dict.php` de la version Dolibarr installée pour les colonnes `entity`. Aucun écran de configuration parallèle n'est ajouté dans cette étape.

## Compatibilité

Le socle repose uniquement sur des APIs disponibles à partir de Dolibarr v20 et PHP 8.0 : descripteur de module, fichiers SQL, extrafields, dictionnaires natifs et hooks Multicompany déjà utilisés par le module.
