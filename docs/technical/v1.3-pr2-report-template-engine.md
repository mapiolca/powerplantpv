# PR2 - Moteur de Modèles de Rapports Configurables

## Objet

Cette PR ajoute un moteur générique de configuration des rapports d'intervention. Le moteur couvre uniquement la configuration : modèles, sections, champs, options, mappings prestations -> sections et association nature d'intervention -> modèle. L'onglet de saisie du rapport dans les interventions et la génération PDF restent hors périmètre.

La maintenance préventive est représentée par le modèle préinstallé `preventive_maintenance`. Elle ne doit plus être traitée comme un cas codé en dur.

## Modèle de données

### `powerplantpv_report_template`

Table principale des modèles :

| Colonne | Rôle |
|---|---|
| `entity` | Entité Dolibarr propriétaire |
| `code` | Code technique unique par entité |
| `label`, `label_en` | Libellés |
| `description`, `description_en` | Descriptions |
| `target_element` | Objet cible, actuellement `fichinter` |
| `is_default` | Modèle par défaut de l'entité |
| `active` | Activation fonctionnelle |
| `position` | Ordre d'affichage |
| `date_creation`, `tms`, `fk_user_creat`, `fk_user_modif` | Traçabilité |

### `powerplantpv_report_template_section`

Table des sections d'un modèle :

| Colonne | Rôle |
|---|---|
| `fk_report_template` | Modèle parent |
| `code` | Code technique unique dans le modèle |
| `scope_type` | Portée de la section |
| `equipment_type` | Type d'équipement ciblé, facultatif |
| `repeat_mode` | Mode de répétition |
| `is_required` | Section obligatoire |
| `visible_form`, `visible_pdf` | Visibilité future formulaire / PDF |
| `active`, `position` | Activation et ordre |

### `powerplantpv_report_template_field`

Table des champs d'une section. Les colonnes PR1 `report_template_code` et `fk_report_section` restent présentes pour migration et compatibilité historique. Les nouvelles colonnes de référence sont `fk_report_template` et `fk_report_template_section`.

Les champs portent le type, la valeur par défaut, le placeholder, l'aide, les flags obligatoire / visible / lecture seule, l'ordre et la traçabilité.

### `powerplantpv_report_template_field_option`

Table des options pour les champs `select`, `multiselect` et assimilés :

| Colonne | Rôle |
|---|---|
| `fk_report_template_field` | Champ parent |
| `code` | Code technique |
| `label`, `label_en` | Libellés |
| `active`, `position` | Activation et ordre |

### `powerplantpv_maintenance_service_section`

Table de mapping prestations -> sections. Les nouvelles références sont `fk_report_template` et `fk_report_template_section`; l'ancien `fk_report_section` reste pour migration historique.

### `c_powerplantpv_intervention_nature`

Le dictionnaire des natures d'intervention reçoit `fk_report_template`. La colonne `report_template_code` reste synchronisée comme compatibilité historique.

## Règles de configuration

- Les codes techniques sont uniques dans leur périmètre et restent stables.
- Chaque donnée métier est filtrée strictement par `entity`.
- Les actions de création, modification, désactivation, suppression, duplication et réordonnancement passent par les classes métier.
- Les suppressions restent possibles pour l'administration, mais la désactivation est le comportement recommandé.
- La duplication d'un modèle copie sections, champs, options et mappings prestations. La copie est inactive, non définie par défaut et ne réassocie aucune nature d'intervention.

## Migration PR1

Les anciennes définitions PR1 sont migrées vers `preventive_maintenance` :

| Ancienne valeur | Nouvelle valeur |
|---|---|
| `boolean` | `yesno` |
| `status` | `conformity_so_valid_obs` |
| `varchar` | `text` |
| `double` | `number` |
| `text` | `textarea` |
| `per_powerplant` | `once_per_powerplant` |
| `per_equipment` | `once_per_equipment` |
| `dynamic_rows` | `user_defined_lines` |
| `dc_measure` | `pv_input` |
| `roof` | `roof_area` |
| `thermography` | `free_line` |

Le dictionnaire historique `c_powerplantpv_report_section` est conservé comme source de migration, mais il n'est plus exposé comme dictionnaire d'administration actif.

## Options préinstallées

Le seed idempotent ajoute les options utiles suivantes selon les champs :

- conformité : `CONFORME`, `NON_CONFORME`, `SO` ;
- criticité : `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` ;
- oui / non : `YES`, `NO` ;
- thermographie : anomalies de base pour `THERMO_ANOMALY_TYPE`.

## Écrans d'administration

Les pages internes aux réglages du module sont :

- `admin/maintenance_report_templates.php`
- `admin/maintenance_report_template_card.php`
- `admin/maintenance_report_template_sections.php`
- `admin/maintenance_report_template_fields.php`
- `admin/maintenance_service_sections.php`
- `admin/maintenance_intervention_natures.php`

Elles sont limitées au droit `powerplantpv / maintenance / config`, avec bypass administrateur Dolibarr via le helper central.

## Limites restantes

- Pas d'onglet Rapport dans les interventions dans cette PR.
- Pas de saisie effective des données de rapport.
- Pas de génération PDF.
- Pas de modèle documentaire associé au moteur.
- Pas d'API REST dédiée au moteur dans cette PR.
