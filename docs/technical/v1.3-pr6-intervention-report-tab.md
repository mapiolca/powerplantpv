# PR6 - Onglet Rapport des interventions

## Objectif

PR6 ajoute l'onglet `Rapport` aux fiches interventions Dolibarr.

Le rapport est généré depuis :

- la nature d'intervention portée par l'extrafield `powerplantpv_intervention_nature` ;
- le modèle de rapport actif associé à cette nature ;
- les centrales liées à l'intervention par les liens natifs Dolibarr ;
- les contrats liés à l'intervention ou aux centrales ;
- les services actifs de contrat et leurs prestations de maintenance ;
- les équipements connus des centrales lorsque les données sont disponibles.

Le PDF complet n'est pas généré dans PR6.

## Onglet

Le descripteur déclare l'onglet :

```text
intervention:+powerplantpv_report
```

Il pointe vers :

```text
/powerplantpv/maintenance_intervention_report.php?id=__ID__
```

La page reprend le rendu d'une fiche native : chargement Dolibarr standard, droits serveur, entête de fiche, onglets, bannière intervention, messages `setEventMessages()` et actions POST protégées par token.

## Génération sans écriture en GET

À l'ouverture de l'onglet :

1. la page charge l'intervention ;
2. elle lit la nature d'intervention ;
3. elle recherche le modèle de rapport actif associé ;
4. elle calcule un aperçu du formulaire si aucun rapport n'existe ;
5. elle affiche le snapshot existant si un rapport a déjà été créé.

Un simple `GET` ne crée aucun enregistrement. Le snapshot est créé uniquement au premier `POST` de sauvegarde.

## Snapshot

Le premier enregistrement crée :

- `llx_powerplantpv_report` ;
- `llx_powerplantpv_report_powerplant` ;
- `llx_powerplantpv_report_source_service` ;
- `llx_powerplantpv_report_equipment` ;
- `llx_powerplantpv_report_section` ;
- `llx_powerplantpv_report_field`.

Les sections et champs affichés ensuite proviennent uniquement du snapshot. Une modification ultérieure du modèle de rapport ne modifie donc pas un rapport existant.

Les options de champs sont figées dans `options_snapshot`. Cette copie est un instantané technique du formulaire, pas une source de vérité métier.

## Prestations

Le builder recherche les prestations depuis :

- les contrats liés directement à l'intervention ;
- les contrats liés aux centrales de l'intervention ;
- les lignes `contratdet` actives ;
- les produits/services de type service ;
- l'extrafield produit `powerplantpv_maintenance_services`.

Si aucune prestation contractuelle n'est trouvée, l'onglet affiche un message clair. Les utilisateurs ayant `powerplantpv->maintenance->report` ou `powerplantpv->maintenance->write` peuvent sélectionner manuellement les prestations à appliquer.

Les prestations manuelles sont figées comme sources avec `source_mode = manual`.

## Recalcul

Le bouton `Recalculer le rapport depuis le modèle` est disponible uniquement si :

- le rapport existe ;
- l'intervention n'est ni signée ni clôturée ;
- l'utilisateur a le droit de modification rapport.

Le recalcul reconstruit le snapshot depuis le modèle courant et conserve les valeurs lorsque la clé stable correspond :

```text
section:<code>[:powerplant:<id>|:equipment:<key>|:manual:1]:field:<field_code>
```

Les fichiers liés aux champs conservés sont rattachés au nouveau champ lorsque la clé stable correspond.

## Sauvegarde

PR6 fournit deux états internes :

- `draft` ;
- `saved`.

Il n'y a pas encore de validation métier propre au rapport. Le verrouillage final dépend de l'intervention : signée ou clôturée.

## Lecture seule

Si l'intervention est signée ou clôturée :

- le formulaire est en lecture seule ;
- aucun bouton de sauvegarde n'est affiché ;
- le recalcul est masqué ;
- l'upload et la suppression de fichiers sont refusés côté serveur.

## Interface mobile

Les sections sont rendues en blocs `<details>` pliables.

Les champs sont affichés en cartes verticales via `css/powerplantpv_report.css`, sans tableau horizontal. Sur mobile, la grille passe sur une seule colonne.

## Limites PR6

- Pas de génération PDF complète.
- Pas de validation dédiée du rapport.
- Les portées MPPT et entrée PV restent conservatrices : si les données détaillées ne sont pas disponibles, le builder crée une occurrence manuelle plutôt qu'une logique MPPT avancée.
- Le fichier joint d'un champ `file` est stocké dans l'espace documentaire du module, sous le répertoire de l'entité du rapport.

## Tests manuels

- Intervention sans nature : message clair, aucun snapshot.
- Nature sans modèle : message clair, aucun snapshot.
- Nature avec modèle actif : aperçu puis création du snapshot au premier enregistrement.
- Sauvegarde brouillon et sauvegarde simple.
- Modification du modèle après snapshot : aucun impact sans recalcul.
- Recalcul avant signature/clôture : valeurs conservées par clé stable.
- Intervention signée ou clôturée : lecture seule et actions refusées.
- Mode manuel de prestations si aucun service contractuel n'en fournit.
- Upload et suppression sur champ `file`.
- Affichage mobile sans tableau horizontal.
- Désactivation/réactivation du module sans doublon SQL.
