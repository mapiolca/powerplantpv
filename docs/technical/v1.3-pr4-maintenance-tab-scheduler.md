# PR4 - Onglet Maintenance centrale et moteur d'échéances

## Objectif

PR4 ajoute un onglet `Maintenance` sur la fiche centrale et un moteur de calcul dédié :

- `class/powerplantpvmaintenancescheduler.class.php`
- `powerplant_maintenance.php`

Le périmètre reste volontairement limité à la fiche centrale. Le menu global Maintenance, le calendrier global et le PDF de maintenance ne sont pas implémentés dans cette étape.

## Sources de données

Le moteur lit uniquement des données Dolibarr existantes ou créées par le socle maintenance :

- liens natifs `element_element` entre la centrale et les contrats/interventions ;
- types de lien centrale compatibles : `powerplantpv_powerplant`, `powerplant@powerplantpv`, `powerplant` ;
- contrats Dolibarr validés et visibles dans `getEntity('contrat')` ;
- lignes de contrat de type service avec `ContratLigne::STATUS_OPEN` ;
- prestations de maintenance issues de `product_extrafields.powerplantpv_maintenance_services`, résolues dans `c_powerplantpv_maintenance_service` ;
- récurrence lue dans `contrat_extrafields.powerplantpv_maintenance_recurrence` ;
- période attendue lue dans `contrat_extrafields.powerplantpv_next_maintenance_period_start` et `contrat_extrafields.powerplantpv_next_maintenance_period_end` ;
- interventions Dolibarr liées à la centrale et visibles dans `getEntity('fichinter')` ;
- nature d'intervention lue dans `fichinter_extrafields.powerplantpv_intervention_nature`, résolue dans `c_powerplantpv_intervention_nature`.

La récurrence supporte les codes `monthly`, `quarterly`, `halfyearly`, `yearly`, `biennial` et `custom`. PR4 affiche et valide ces codes, mais ne génère pas de nouvelle période à partir de la récurrence.

## Statuts calculés

Le moteur retourne les statuts suivants :

| Statut | Libellé | Règle |
|---|---|---|
| `not_required` | Aucune maintenance à prévoir | Aucun contrat éligible ou aucun service actif avec prestation de maintenance. |
| `planned` | À prévoir | Une période est configurée et commence après aujourd'hui. |
| `due` | En cours | Aujourd'hui est compris dans la période configurée. |
| `overdue` | En retard | La période configurée est dépassée et aucune intervention couvrante n'existe. |
| `covered` | Couverte | Une intervention compatible couvre la période attendue. |
| `incomplete` | À configurer | Des prestations de maintenance existent, mais la période de prochaine maintenance est incomplète. |

Si une intervention existe mais n'est ni clôturée ni signée par le destinataire ou par toutes les parties, elle ne couvre pas la période. La maintenance reste donc `planned`, `due` ou `overdue` selon les dates.

## Intervention couvrante

Une intervention couvre une période de maintenance si toutes les conditions suivantes sont vraies :

- l'intervention est liée à la centrale via les liens natifs ;
- si l'intervention porte un `fk_contrat` ou un lien natif vers un contrat, ce contrat correspond au contrat de maintenance évalué ;
- la nature d'intervention est active et marquée maintenance dans `c_powerplantpv_intervention_nature` ;
- l'intervention est clôturée ou signée ;
- sa date ou son intervalle d'intervention chevauche la période attendue.

Les statuts Dolibarr v20 utilisés pour considérer une intervention comme couvrante sont :

- `Fichinter::STATUS_CLOSED` pour une intervention clôturée ;
- `Fichinter::STATUS_SIGNED_RECEIVER` pour une intervention signée par le destinataire ;
- `Fichinter::STATUS_SIGNED_ALL` pour une intervention signée par toutes les parties.

Ces constantes existent dans `htdocs/fichinter/class/fichinter.class.php` en Dolibarr v20. Les services actifs de contrat utilisent `ContratLigne::STATUS_OPEN` depuis `htdocs/contrat/class/contrat.class.php`.

## Interface

L'onglet `Maintenance` est ajouté après les onglets transverses natifs de la centrale, notamment après `Événements/Agenda`, et avant les onglets ajoutés par d'autres modules.

Il affiche :

- une synthèse du statut de maintenance ;
- les contrats liés éligibles ;
- les services actifs ;
- les prestations de maintenance associées ;
- la récurrence ;
- la période de prochaine maintenance ;
- la dernière intervention couvrante ;
- les interventions liées ;
- un bouton `Créer une intervention de maintenance` par ligne éligible.

Le bouton ouvre `/fichinter/card.php?action=create` avec le contexte suivant :

- centrale liée via les paramètres PR3 ;
- contrat transmis par `contratid` et `fk_contrat` ;
- nature `PREVENTIVE_MAINTENANCE` transmise par code ;
- période transmise par paramètres PowerPlantPV et insérée dans la description lorsque la période existe.

## Limites connues

- PR4 ne crée pas de menu global Maintenance.
- PR4 ne crée pas de calendrier global.
- PR4 ne génère pas de PDF de maintenance.
- PR4 ne calcule pas automatiquement les périodes suivantes à partir de la récurrence.
- Les contrats sans période configurée restent en statut `incomplete` dès lors qu'ils ont un service actif avec prestation de maintenance.
- Une intervention ouverte ou non signée ne couvre jamais la période, même si elle est liée à la centrale.

## Tests manuels

À vérifier sur une instance Dolibarr avec le module activé :

- centrale sans contrat lié : statut `Aucune maintenance à prévoir` ;
- centrale avec contrat lié sans service actif : statut `Aucune maintenance à prévoir` ;
- centrale avec service actif sans prestation de maintenance : statut `Aucune maintenance à prévoir` ;
- centrale avec service actif et prestation de maintenance, période future : statut `À prévoir` ;
- centrale avec période incluant la date du jour : statut `En cours` ;
- centrale avec période passée sans intervention couvrante : statut `En retard` ;
- centrale avec prestation de maintenance mais période vide : statut `À configurer` ;
- intervention clôturée liée à la centrale, nature maintenance, période chevauchante : statut `Couverte` ;
- intervention signée destinataire ou toutes parties, nature maintenance, période chevauchante : statut `Couverte` ;
- intervention ouverte non signée : la maintenance reste `À prévoir`, `En cours` ou `En retard` selon les dates ;
- intervention liée à un autre contrat : ne couvre pas le contrat évalué si le lien contrat existe ;
- bouton `Créer une intervention de maintenance` : centrale, contrat, nature `PREVENTIVE_MAINTENANCE` et période de contexte sont préremplis.
