# PR10 - PDF dynamique des rapports d'intervention

## Objectif

PR10 ajoute le modèle PDF Dolibarr `powerplantpvreport` pour les interventions (`ficheinter`). Le PDF est généré depuis l'intervention et lit le snapshot `PowerPlantPVReport` lorsqu'il existe.

Le rendu reste générique : il ne code pas un PDF spécifique à la maintenance préventive. La maintenance préventive est seulement le premier modèle supporté par le moteur de modèles et par les rendus spécialisés de sections connues.

## Modèle PDF

| Élément | Valeur |
|---|---|
| Fichier | `core/modules/fichinter/doc/pdf_powerplantpvreport.modules.php` |
| Classe | `pdf_powerplantpvreport` |
| Type Dolibarr | `ficheinter` |
| Nom modèle | `powerplantpvreport` |
| Sortie | Répertoire documentaire de l'intervention via `getMultidirOutput($object, 'ficheinter', 1)` |
| Fichier | `<ref_intervention>.pdf` |

Le modèle est enregistré à l'activation du module dans `document_model` par insertion idempotente. Il ne devient pas automatiquement le modèle Fichinter par défaut et ne modifie pas `FICHEINTER_ADDON_PDF`.

Le modèle exécute les hooks natifs `beforePDFCreation` et `afterPDFCreation` dans le contexte `pdfgeneration`.

## Source des données

Le chargement est isolé dans `class/powerplantpvreportpdfdataset.class.php`.

Le dataset lit :

- l'intervention Dolibarr ;
- le tiers/client ;
- le projet lié si disponible ;
- les contacts internes natifs de l'intervention ;
- le dernier snapshot `PowerPlantPVReport` via `fetchByIntervention()` ;
- l'arbre du rapport via `PowerPlantPVReportBuilder::loadReportTree()` ;
- les centrales, équipements, sections, champs, fichiers et mesures DC du snapshot ;
- les prestations sources et contrats via `PowerPlantPVReportSourceService::fetchAllByReport()`.

Si aucun snapshot n'existe, le PDF reste générable et affiche un rapport minimal avec un message indiquant qu'aucun rapport n'a été saisi. La génération PDF ne crée pas de snapshot.

## Rendu

Le PDF affiche :

- l'en-tête société ;
- le titre du rapport ;
- les informations client, projet et intervention ;
- la nature d'intervention et le modèle de rapport figés ;
- les contrats liés ;
- les centrales concernées ;
- les sections générales puis les sections groupées par centrale ;
- les équipements figés dans le snapshot ;
- les fichiers et photos lisibles ;
- les signatures lorsqu'elles sont présentes ;
- les mentions légales configurées dans `POWERPLANTPV_REPORT_PDF_LEGAL_NOTICE`.

Les sections respectent `visible_pdf`. Une section visible mais vide affiche un bloc discret `NoRecordFound`.

## Rendus spécialisés

Les champs sont rendus depuis leur snapshot : `field_type`, `field_label`, `unit`, `options_snapshot`, `value_text`, `value_number`, `value_date`.

Les sections connues bénéficient d'un rendu spécialisé :

- `DC_ELECTRICAL_MEASURE` : tableau des mesures DC par onduleur, MPPT, entrée PV et string ;
- `PRODUCTION_READING` : appairage des champs `*_N_MINUS_1` et `*`, affichage N-1, N, delta, unité et observation ;
- `THERMOGRAPHY` : données thermographiques et séparation des photos visibles et thermographiques ;
- champs `signature` : affichage du libellé, de la valeur et de l'image de signature si un fichier image est lié.

Les autres sections restent rendues génériquement.

## Images et fichiers

Les fichiers du rapport sont résolus depuis le répertoire documentaire PowerPlantPV de l'entité propriétaire du rapport.

Les images lisibles sont intégrées au PDF. Les images absentes ou illisibles ne bloquent pas la génération : une mention est affichée. Les fichiers non image sont listés par nom.

## Pied de page

Le modèle réserve une zone de pied de page avant le rendu du contenu avec `setPageOrientation('', true, $heightforfooter)`.

Les pieds de page sont rendus page par page avec `pdf_pagefoot()` :

- pages intermédiaires : texte libre masqué ;
- dernière page : texte libre et mention légale affichés si configurés.

## Limites

- Les signatures avancées ne sont pas créées par le PDF ; le modèle affiche uniquement les champs et fichiers déjà présents dans le snapshot.
- Les photos intégrées doivent être des fichiers lisibles dans le stockage documentaire attendu.
- Les champs inconnus restent affichés avec le rendu générique.
- Le PDF ne recalcule pas le rapport et ne synchronise pas les relevés ; ces traitements restent portés par le moteur de rapport.

## Procédure de test

Exécuter les vérifications PHP :

```bash
php -l class/powerplantpvreportpdfdataset.class.php
php -l core/modules/fichinter/doc/pdf_powerplantpvreport.modules.php
php -l core/modules/modPowerPlantPV.class.php
php -l admin/setup.php
php -l class/powerplantpvcompatibility.class.php
```

Tests fonctionnels attendus :

- intervention sans rapport ;
- rapport simple ;
- maintenance préventive ;
- multi-centrales ;
- multi-équipements ;
- mesures DC ;
- relevés N-1 / N / delta ;
- thermographie avec photos ;
- signature client et technicien ;
- image ou fichier manquant ;
- génération dans deux entités différentes ;
- objet partagé consulté depuis une autre entité autorisée.
