# PowerPlantPV v1.3 PR3 - Liaisons natives centrales / contrats / interventions

Copyright (C) 2026  Pierre Ardoin <developpeur@lesmetiersdubatiment.fr>

## Objectif

Cette étape ajoute une liaison rapide multi-centrales sur les fiches contrat et intervention.
La source de vérité reste la table native Dolibarr `llx_element_element`.

Aucune colonne `fk_powerplant` n'est ajoutée aux contrats ou aux interventions.

## Mécanisme de liaison

Les liaisons sont créées, modifiées et supprimées avec les méthodes natives `CommonObject` :

- `add_object_linked()` pour ajouter une liaison ;
- `deleteObjectLinked()` pour supprimer une ligne de liaison native.

Le type canonique utilisé pour les nouvelles liaisons de centrale est :

```text
powerplantpv_powerplant
```

Les anciennes formes restent lues pour compatibilité :

```text
powerplant@powerplantpv
powerplant
```

Lorsqu'un utilisateur enregistre la sélection rapide, le module lit les liens existants dans les deux sens, supprime les lignes non sélectionnées ou non canoniques, puis ajoute les liens manquants avec le type canonique.

## Types d'objets

| Objet | Type Dolibarr utilisé dans `element_element` |
|---|---|
| Centrale PowerPlantPV | `powerplantpv_powerplant` |
| Contrat | `contrat` |
| Intervention | `fichinter` |

## Hooks utilisés

Le descripteur déclare les contextes :

- `contractcard` ;
- `interventioncard` ;
- `fichintercard` ;
- `commonobject`.

La classe `ActionsPowerplantpv` utilise :

- `formObjectOptions` pour ajouter le multiselect `Centrale(s)` dans les formulaires de création contrat/intervention ;
- `formConfirm` pour afficher un bloc rapide sur les fiches existantes ;
- `doActions` pour traiter le POST `powerplantpv_set_powerplants` et injecter les objets liés dans le payload natif de création.

Le bloc rapide ne remplace pas le bloc natif **Objets liés** affiché par Dolibarr. Il sert uniquement à accélérer la sélection multi-centrales.

## Exemple contrat -> centrale

Sur une fiche contrat existante, l'utilisateur sélectionne une ou plusieurs centrales dans le bloc **Centrales liées**.

Le module synchronise les lignes natives :

```text
sourcetype = contrat
fk_source  = <contrat.rowid>
targettype = powerplantpv_powerplant
fk_target  = <powerplantpv_powerplant.rowid>
```

Une centrale déjà liée avec un ancien type reste détectée. Lors d'une mise à jour de la sélection, le lien est recréé au format canonique.

## Exemple intervention -> centrale

Sur une fiche intervention existante, la sélection multi-centrales crée les lignes :

```text
sourcetype = fichinter
fk_source  = <fichinter.rowid>
targettype = powerplantpv_powerplant
fk_target  = <powerplantpv_powerplant.rowid>
```

Une intervention peut donc concerner plusieurs centrales sans colonne spécifique dans `fichinter`.

## Liaison automatique intervention -> contrat de maintenance

Lorsqu'une intervention Dolibarr est créée avec une nature PowerPlantPV active marquée maintenance, le service `PowerPlantPVMaintenanceContractLinker` cherche les contrats de maintenance actifs des centrales liées ou demandées à la création.

Un contrat est candidat s'il est validé, lié à la centrale via `element_element`, et s'il possède au moins une ligne de service active dont le produit ou service porte une prestation de maintenance PowerPlantPV.

Si aucun contrat n'est déjà transmis par `fk_contrat`, `contratid`, `origin=contrat` ou `other_linked_objects`, le meilleur candidat est injecté dans le payload natif de création et ajouté comme lien natif intervention-contrat. Le tri retient la période de maintenance la plus récente, puis le `rowid` contrat le plus élevé en cas d'égalité.

Le traitement est idempotent : il ne remplace pas un contrat existant et ne crée pas de table de liaison spécifique.

## Préremplissage

La création d'intervention accepte les paramètres :

- `powerplantpv_powerplants[]` ;
- `fk_powerplant` ;
- `fk_contrat` ou `contratid` ;
- `origin=powerplantpv_powerplant&originid=<id>` ;
- `origin=contrat&originid=<id>` ;
- `powerplantpv_intervention_nature` ;
- `powerplantpv_intervention_nature_code`.

Si l'intervention est créée depuis une centrale, la centrale est préselectionnée.

Si l'intervention est créée depuis un contrat ou depuis un paramètre `fk_contrat` / `contratid`, les centrales déjà liées au contrat sont préselectionnées. Le contrat est aussi injecté dans les objets liés natifs si le core ne le porte pas déjà par `origin`.

La nature d'intervention peut être préremplie par identifiant ou par code du dictionnaire `c_powerplantpv_intervention_nature`.

## Droits et Multicompany

Le bloc est affiché uniquement si l'utilisateur dispose :

- des droits de lecture de l'objet core concerné ;
- du droit PowerPlantPV `powerplant/read` ;
- du droit PowerPlantPV `maintenance/read`.

La modification exige en plus :

- le droit core de création/modification du contrat ou de l'intervention ;
- le droit PowerPlantPV `maintenance/write`.

La liste des centrales sélectionnables est filtrée par `getEntity('powerplant')` et par le tiers courant lorsque l'objet en porte un. Pour un utilisateur externe, le tiers de l'utilisateur reste imposé.

## Limites

Cette PR ne livre pas :

- le calcul complet des échéances de maintenance ;
- l'onglet Maintenance complet ;
- l'onglet Rapport d'intervention ;
- la génération ou la saisie du rapport de maintenance ;
- une table de liaison spécifique PowerPlantPV pour contrats ou interventions.

Les futures échéances de maintenance devront réutiliser les paramètres et les types de liaison décrits ici au lieu d'ajouter une source de vérité parallèle.
