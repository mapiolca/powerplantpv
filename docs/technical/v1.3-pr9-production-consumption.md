# PR9 - Production/consommation

## Objectif

PR9 ajoute un historique de relevés d'index sur la fiche centrale. Les relevés peuvent être saisis manuellement ou archivés depuis la section `PRODUCTION_READING` des rapports d'intervention.

Le PDF de maintenance reste hors périmètre et sera traité dans PR10.

## Données ajoutées

| Table | Rôle |
|---|---|
| `powerplantpv_index_reading` | Archive active/inactive des relevés de production, injection, consommation et autoconsommation |

Chaque relevé porte la centrale, le type de relevé, la date, la valeur, l'unité, une référence compteur/onduleur optionnelle, la source et les liens éventuels vers intervention, rapport, centrale de rapport et équipement de rapport.

Les types de relevés restent dans le dictionnaire `c_powerplantpv_index_type` :

- `INVERTER_PRODUCTION` ;
- `PRODUCTION_INDEX` ;
- `INJECTION_INDEX` ;
- `CONSUMPTION_INDEX` ;
- `ANNUAL_PRODUCTION` ;
- `SELF_CONSUMPTION` ;
- `OTHER`.

## Onglet centrale

La fiche centrale expose l'onglet `Production/consommation` après les onglets natifs et maintenance.

L'onglet affiche une liste native avec :

- date du relevé ;
- type ;
- valeur ;
- unité ;
- delta avec le relevé précédent du même type pour la même centrale ;
- utilisateur de création ;
- source ;
- intervention source ;
- rapport source ;
- commentaire.

Le bouton `Relever l'index de production` ouvre un formulaire rapide sur la même page. La centrale courante est imposée côté serveur.

## Saisie manuelle

Une saisie manuelle renseigne :

- `source_type = manual` ;
- `fk_powerplant = centrale courante` ;
- `fk_user_creat = utilisateur courant` ;
- `fk_fichinter_source = NULL` ;
- `fk_report = NULL` ;
- `unit = kWh` par défaut.

Le formulaire utilise le datepicker natif Dolibarr, le dictionnaire des types et un token CSRF.

## Synchronisation depuis rapport

La section `PRODUCTION_READING` du rapport utilise les champs `N-1` comme valeurs d'information non éditables. Lors de la génération ou du recalcul du snapshot, ces champs sont préremplis depuis le dernier relevé actif archivé pour la même centrale et le même type.

Les champs `N` non vides sont archivés uniquement quand le rapport est enregistré au statut `saved`. Les sauvegardes brouillon et les recalculs désactivent les anciennes lignes archivées de ce rapport afin de ne pas afficher de valeurs provisoires.

La date d'un relevé issu d'un rapport est résolue dans cet ordre :

1. date d'intervention ;
2. autre date disponible sur l'intervention ;
3. date de création du rapport ;
4. `dol_now()`.

## Anti-doublon

Un relevé issu d'un rapport est unique par :

- `entity` ;
- `fk_powerplant` ;
- `fk_fichinter_source` ;
- `fk_report` ;
- `reading_type_code` ;
- `meter_ref` ;
- `fk_report_equipment`.

Lorsqu'un rapport finalisé est modifié puis enregistré à nouveau, la ligne existante est mise à jour ou réactivée. Le module ne crée pas de doublon.

## Multi-centrales

Les occurrences de section `PRODUCTION_READING` sont générées par centrale. La synchronisation lit la centrale source depuis le snapshot `powerplantpv_report_powerplant`, puis archive chaque relevé dans la centrale correspondante.

L'onglet d'une centrale filtre strictement `fk_powerplant` et n'affiche pas les relevés des autres centrales.

## Droits

Lecture :

- administrateur ;
- droit centrale `powerplant/read` ;
- ou droit maintenance `maintenance/read`.

Création/modification :

- administrateur ;
- droit centrale `powerplant/write` ;
- ou droit maintenance `maintenance/write`.

Le contrôle d'accès reste complété par `restrictedArea()` sur l'objet centrale.

## Tests fonctionnels attendus

- onglet visible sur une centrale autorisée ;
- saisie manuelle avec unité `kWh` par défaut ;
- delta calculé avec le relevé actif précédent du même type ;
- relevé manuel sans intervention ni rapport source ;
- relevé issu d'une intervention et d'un rapport source ;
- modification d'un rapport finalisé sans doublon ;
- sauvegarde brouillon/recalcul d'un rapport : anciennes lignes du rapport désactivées ;
- intervention liée à plusieurs centrales : archivage par centrale ;
- accès refusé sans droit centrale ni droit maintenance ;
- activation/réactivation du module sans doublon SQL.
