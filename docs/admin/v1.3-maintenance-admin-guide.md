# Guide administrateur v1.3 Maintenance

Ce guide décrit la configuration de PowerPlantPV 1.3 Maintenance dans Dolibarr. Les réglages sont à effectuer par entité lorsque Multicompany est utilisé.

## Activation

1. Déployer le module dans `htdocs/custom/powerplantpv`.
2. Activer PowerPlantPV depuis la liste des modules Dolibarr.
3. Vérifier l'onglet de réglages `Compatibilité`.
4. Vérifier que le fichier `modulebuilder.txt` est présent à la racine du module.
5. Réactiver une seconde fois en environnement de recette pour confirmer l'idempotence des tables, dictionnaires et modèles.

La réactivation ne doit pas supprimer les constantes, modèles, réglages de rapports, options Agenda/Notifications ou personnalisations de dictionnaires.

## Rappels automatiques

Les réglages PowerPlantPV permettent de configurer deux rappels de maintenance :

- rappel hebdomadaire ;
- rappel mensuel.

Chaque rappel dispose d'un switch d'activation et d'une date/heure de départ. Les travaux planifiés natifs PowerPlantPV exécutent ensuite l'envoi à partir de cette date, puis programment le prochain départ.

Configurer aussi :

- le délai de bascule d'une maintenance future de `Couverte` vers `À prévoir`, par défaut 30 jours avant le début de la prochaine période ;
- les utilisateurs Dolibarr destinataires, qui doivent être actifs et avoir une adresse email ;
- le modèle d'email optionnel. Si aucun modèle n'est choisi, PowerPlantPV envoie un message par défaut. Si un modèle est choisi mais ne contient pas les substitutions maintenance, le tableau des maintenances est ajouté automatiquement.

Les rappels listent les maintenances `À prévoir`, `En cours` et `En retard`, avec centrale, contrat, période, statut et prestations.

## Droits

Attribuer les droits selon les profils :

- `powerplant/read` : consultation des centrales ;
- `powerplant/write` : modification des centrales ;
- `maintenance/read` : consultation maintenance, calendrier, statistiques et rapports ;
- `maintenance/write` : création et modification des données de maintenance ;
- `maintenance/report` : saisie et recalcul des rapports ;
- `maintenance/delete` : suppression lorsque les écrans le permettent ;
- `maintenance/config` : administration des natures, modèles, sections, champs et mappings.

Les administrateurs Dolibarr gardent un accès fonctionnel complet. Les utilisateurs standards restent soumis aux droits granulaires.

## Dictionnaires

Les dictionnaires de maintenance sont installés de façon idempotente :

- natures d'intervention ;
- prestations de maintenance ;
- types de sections ;
- types de relevés de production/consommation.

Ne pas supprimer une ligne utilisée en production. Désactiver une ligne est préférable si elle ne doit plus être proposée.

## Natures d'intervention

Les natures d'intervention associent une intervention à un modèle de rapport.

Pour la maintenance préventive, la nature préinstallée pointe vers le modèle `preventive_maintenance`. Elle indique que l'intervention relève de la maintenance, qu'elle peut exiger un rapport et qu'elle peut exiger une signature selon votre usage.

## Modèles de rapport

Les modèles de rapport sont administrés depuis les onglets internes de réglages PowerPlantPV.

Un modèle contient :

- des sections ;
- des champs ;
- des options de champs ;
- des mappings prestation/section ;
- une association avec les natures d'intervention.

Le modèle préinstallé `preventive_maintenance` sert de base. Pour une personnalisation importante, dupliquer le modèle puis modifier la copie.

## Sections

Une section définit une zone du rapport. Les sections peuvent être générales, liées à une centrale ou répétées par équipement.

Les sections utilisées par les prestations ne doivent pas changer de code après usage. Le code participe aux clés stables de snapshot et de recalcul.

## Champs

Un champ définit une donnée saisie dans le rapport :

- texte ;
- zone longue ;
- nombre ;
- date ;
- oui/non ;
- liste ;
- multisélection ;
- fichier ;
- signature ;
- champ calculé.

Les codes de champs doivent rester stables. Modifier un libellé est peu risqué ; modifier un code peut empêcher la conservation de valeurs lors d'un recalcul.

## Points de contrôle

Les points de contrôle sont modélisés par les champs du rapport et leurs options. Pour les contrôles conformes/non conformes/observation, utiliser les types de champs prévus par le modèle plutôt qu'un champ texte libre.

## Prestations

Une prestation de maintenance décrit un contenu opérationnel tel que contrôle visuel, mesures DC, thermographie ou relevés de production.

Elle est rattachée :

- aux produits/services Dolibarr via les champs complémentaires PowerPlantPV ;
- aux sections via les mappings prestation/section.

Un service de contrat actif portant ces prestations déclenche les sections correspondantes dans le rapport.

## Données par défaut

L'activation installe des données par défaut non destructives :

- nature `PREVENTIVE_MAINTENANCE` ;
- modèle `preventive_maintenance` ;
- sections et champs de base ;
- options de contrôle ;
- mappings entre prestations et sections ;
- modèle PDF `powerplantpvreport` pour les interventions.

Les valeurs personnalisées déjà présentes ne doivent pas être écrasées par une réactivation.

## Précautions avant personnalisation

- Travailler d'abord en recette.
- Dupliquer le modèle préinstallé pour les variantes client.
- Ne pas renommer les codes techniques après utilisation.
- Ne pas supprimer les prestations ou sections déjà référencées par des rapports.
- Tester un rapport brouillon, un rapport enregistré, un recalcul et un PDF.
- Tester au moins une centrale avec plusieurs équipements et une intervention multi-centrales si ce cas existe.
- En Multicompany, vérifier chaque entité concernée.

## Recette administrateur minimale

- Activation sans erreur.
- Réactivation sans doublon.
- Les droits apparaissent dans les fiches utilisateurs/groupes.
- Les dictionnaires maintenance sont visibles.
- Le modèle `preventive_maintenance` existe et reste personnalisable.
- Le modèle PDF `powerplantpvreport` est disponible sur les interventions.
- Les réglages de modèles et dictionnaires sont conservés après réactivation.
- Les travaux planifiés hebdomadaire et mensuel de rappel apparaissent dans les travaux planifiés Dolibarr.
- Un rappel activé sans destinataire ou sans maintenance à traiter ne provoque pas d'erreur fatale.
